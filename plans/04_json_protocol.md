# 04 — بروتوكول JSON الموحّد (Pi ↔ Arduino)

> المشكلة الحالية: بروتوكول الأردوينو والبايثون **غير متطابقين**. هذا الملف يوحّدهما.

---

## 1. عدم التطابق الحالي (للتوثيق)

| الجانب | ما يرسله فعلياً | الملاحظة |
|---|---|---|
| `motors.py` → الأردوينو | `{"type":"motor","m1":..,"m2":..,"s1":..,"s2":..}` | يحلّ أوامر الاتجاه محلياً إلى m1/m2 (لا يرسل `direction`) |
| الأردوينو الحالي يفهم | `{"direction":"F","speed":..}` و `{"m1":..,"m2":..,"s1":..,"s2":..}` و `{"stop":true}` | منطق `direction` **كود ميت** لأن البايثون لا يرسله |
| الأردوينو → البايثون | `{"T":..,"D":..,"G":..,"L":..}` + `{"heartbeat":ms}` + صدى `{"m1":..,"s1":..}` + `{"error":..}` | لا يرسل `H` (رطوبة) رغم أن البايثون يتوقعها؛ لا `R` |
| `bluetooth._data_reader_loop` | يبثّ **أي** قاموس وارد كـ `sensor_data` | يخلط heartbeat/ack/error مع الحساسات |

---

## 2. البروتوكول الموحّد المعتمد

### 2.1 الراسبيري → الأردوينو (أوامر)

**أمر اتجاه (4 عجلات):**
```json
{"dir":"F","spd":200}
```
`dir` ∈ `F,B,L,R,FL,FR,BL,BR,SPIN_L,SPIN_R,S` — `spd` ∈ 0..255.

**تحكم مباشر بالمحركات/السيرفو:**
```json
{"m1":200,"m2":200,"m3":200,"m4":200,"s1":90,"s2":90}
```
- `m1..m4`: −255..255 (سالب = عكسي). أي مفتاح غائب = بدون تغيير.
- `s1,s2`: 0..180.

**توقف طارئ:**
```json
{"stop":true}
```

> أزل `"type":"motor"` من `motors._build_command` أو اجعل الأردوينو يتجاهله (يتجاهله أصلاً).
> القرار: **إزالته** لتقليل الحِمل وتوحيد الشكل.

### 2.2 الأردوينو → الراسبيري (تيليمتري)

**قراءات الحساسات (كل ~1s):**
```json
{"T":25.5,"H":60.0,"G":312,"D":34,"R":80}
```
أكواد موحّدة (كبيرة، تطابق `config.yaml` و`SensorManager`):

| كود | المعنى | الوحدة | المصدر |
|---|---|---|---|
| `T` | حرارة | °C | DHT |
| `H` | رطوبة | % | DHT |
| `G` | غاز | ppm (أو خام 0..1023) | MQ2 |
| `D` | مسافة | cm | HC-SR04 |
| `R` | مطر | % (0=جاف,100=مبلل) | Rain A0 |

**نبضة حياة (كل ~2s):**
```json
{"hb":1}
```

**(اختياري) إشعار خطأ:**
```json
{"err":"json"}
```

**ردود المعايرة (انظر `08_eeprom_calibration.md`):**
```json
{"cfg":"dump", ...}      // كل الإعدادات الحالية
{"cfg":"saved"}          // تأكيد الحفظ في EEPROM
{"cfg":"reset_done"}     // تأكيد إعادة الضبط للمصنع
```
> أوامر المعايرة من الراسبيري تبدأ بمفتاح `"cfg"` (تعديل/حفظ) أو `"cal"` (تشغيل تجريبي).

## 3. التوجيه على جانب الراسبيري (إصلاح إلزامي)

`bluetooth._data_reader_loop` يجب أن يوجّه الرسالة حسب نوعها بدل بثّها عمياء:

```python
msg = self.read_json(timeout=0.5)
if not isinstance(msg, dict):
    continue
if "hb" in msg:
    self._last_hb = time.time()          # حيّ
elif "err" in msg:
    logger.warning("Arduino error: %s", msg["err"])
elif "cfg" in msg:                        # ردود المعايرة (dump/saved/reset_done)
    if self._socketio:
        self._socketio.emit("calib_config", msg)   # للواجهة، ليست حساساً
else:
    # قراءات حساسات: مرّرها لمدير الحساسات (تاريخ + تحذيرات + قصّ)
    sensor_codes = {"T","H","G","D","R","L","P"}
    readings = {k: v for k, v in msg.items() if k in sensor_codes}
    if readings and self._sensor_manager:
        self._sensor_manager.update(readings)   # يبثّ sensor_data داخلياً
```
> يتطلّب تمرير مرجع `sensor_manager` إلى `BluetoothManager` (انظر الخطة 05).

---

## 4. أمثلة طرفية كاملة

| الفعل | JSON المُرسَل |
|---|---|
| تقدّم بسرعة 150 | `{"dir":"F","spd":150}` |
| دوران بمكانه يسار | `{"dir":"SPIN_L","spd":200}` |
| محرك أمامي يسار فقط للخلف | `{"m1":-180}` |
| توجيه السيرفو للأمام | `{"s1":90,"s2":90}` |
| طوارئ | `{"stop":true}` |

---

## 5. قواعد ثابتة

1. كل رسالة = سطر JSON واحد منتهٍ بـ `\n`.
2. baud = 9600 على الطرفين (HC-05 الافتراضي).
3. الأكواد الحرفية للحساسات **كبيرة** على الطرفين (T,H,G,D,R).
4. لا ترسل قيم `null`؛ احذف المفتاح بدلاً منها (الأردوينو محدود الذاكرة).
5. الأردوينو لا يردّ صدى لكل أمر (لتقليل ازدحام HC-05) — الـ heartbeat يكفي لإثبات الحياة.
