# 06 — دمج الحساسات (DHT / MQ2 / Ultrasonic / Rain)

يغطّي الطرفين: قراءة الأردوينو + استقبال الراسبيري + تعريفات الواجهة.
الأكواد الموحّدة: `T` حرارة، `H` رطوبة، `G` غاز، `D` مسافة، `R` مطر (انظر `04_json_protocol.md`).

---

## 6.1 DHT (حرارة + رطوبة) — يستبدل LM35

**العتاد:** DHT11 (±2°C، 1Hz) أو DHT22 (±0.5°C، 0.5Hz). على **D2** + مقاومة pull-up 10kΩ.

**الأردوينو:**
```cpp
#include <DHT.h>
#define DHT_PIN 2
#define DHT_TYPE DHT11        // أو DHT22
DHT dht(DHT_PIN, DHT_TYPE);
// setup(): dht.begin();
float t = dht.readTemperature();   // قد ترجع NaN
float h = dht.readHumidity();
if (!isnan(t)) out["T"] = t;
if (!isnan(h)) out["H"] = h;
```
**ملاحظات:**
- لا تقرأ DHT11 أسرع من مرة/ثانية (DHT22 مرة/ثانيتين).
- تجاهل `NaN` (قراءة فاشلة) ولا ترسلها.
- احذف كل كود LM35 (`readTemperature` القديمة بـ `analogRead(A0)` و`TEMP_PIN A0`).

**الراسبيري:** `H` موجود أصلاً في `config.yaml` (أسطر 74–82) وفي الافتراضيات. تأكّد أن الأردوينو يرسله الآن.

---

## 6.2 MQ2 (غاز) — على A1

**العتاد:** خرج تناظري `AO` على A1 (تجاهل `DO` الرقمي). يحتاج **تسخين ~20–60s** قبل قراءات مستقرة.

**الأردوينو:**
```cpp
#define MQ2_PIN A1
int raw = analogRead(MQ2_PIN);     // 0..1023
out["G"] = raw;                    // خام، أو حوّله لـ ppm تقريبية
```
**معايرة تقريبية (اختياري):** MQ2 غير خطّي؛ ppm الدقيقة تحتاج Rs/R0 ومنحنى لوغاريتمي.
للعرض العملي ابدأ بالقيمة الخام (0..1023) أو نسبة مئوية، ووثّق عتبة الإنذار تجريبياً.
في `config.yaml` حساس `G` مداه 0..1000 و`warn_high:300` — عدّل المدى ليطابق ما ترسله
(لو أرسلت خام 0..1023 اجعل `max: 1023`).

## 6.3 Ultrasonic HC-SR04 (مسافة) — TRIG=A3, ECHO=A2

**الأردوينو (بدون مكتبة):**
```cpp
long readUltrasonicCm() {
  digitalWrite(TRIG_PIN, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH); delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);
  long dur = pulseIn(ECHO_PIN, HIGH, 30000UL);   // مهلة 30ms (~5m)
  if (dur == 0) return -1;                         // لا صدى
  return dur * 0.0343 / 2;
}
```
**⚠️ تعارض SoftwareSerial:** أثناء استقبال/إرسال HC-05 تتعطّل المقاطعات فقد يفسد `pulseIn`.
**التخفيف:**
- اقرأ المسافة في نافذة لا يوجد فيها استقبال نشط (`!btSerial.available()`).
- أو استخدم مكتبة **NewPing** (أكثر متانة): `NewPing sonar(A3, A2, 400);` ثم `sonar.ping_cm();`.

**الراسبيري:** `D` موجود في `config.yaml` (أسطر 92–100). أعد `-1`/قيمة خارج المدى تُقصّ تلقائياً
بواسطة `SensorManager.update` (قصّ min/max) — انتبه أن `-1` ستُقصّ إلى `min:2`. فكّر بإرسال
`null`/حذف المفتاح عند فشل القراءة بدل `-1` لتفادي تلوث الرسم البياني.

## 6.4 Rain Sensor (مطر) — على A0 (تناظري)

**العتاد:** لوحة المطر بخرج تناظري `AO` على **A0**. القاعدة الشائعة:
**قيمة منخفضة = ماء أكثر** (المقاومة تقل عند البلل).

**الأردوينو:**
```cpp
#define RAIN_PIN A0
int raw = analogRead(RAIN_PIN);        // 0(مبلل) .. 1023(جاف) عادةً
int rain_pct = map(raw, 0, 1023, 100, 0);   // 100%=مبلل, 0%=جاف
out["R"] = constrain(rain_pct, 0, 100);
```
> اعكس الـ map إن كان موديولك معكوساً. عايره عملياً (جاف vs قطرة ماء).

**الراسبيري:** أضف تعريف الحساس `R` في `config.yaml` (انظر `05 §F17`)،
وأضِف `R` إلى مجموعة `sensor_codes` في توجيه البلوتوث (`04 §3`)،
وتأكّد أن الواجهة تعرض الحساسات ديناميكياً (تقرأ من `sensor_list`/`sensor_data`).

## 6.5 جدول التوافق النهائي (Sensor Matrix)

| كود | الحساس | رجل الأردوينو | مكتبة | config.yaml | ملاحظة |
|---|---|---|---|---|---|
| T | DHT | D2 | DHT.h | موجود | تجاهل NaN |
| H | DHT | D2 | DHT.h | موجود | تجاهل NaN |
| G | MQ2 | A1 | — (analogRead) | عدّل المدى | تسخين أولي |
| D | HC-SR04 | A3/A2 | NewPing (موصى) | موجود | تعارض SoftwareSerial |
| R | Rain | A0 | — (analogRead) | **أضِفه** | عايره |

## 6.6 قائمة تحقق الحساسات

- [ ] DHT يرجع T و H واقعيتين (ليس NaN دائماً → تحقق pull-up والسلك).
- [ ] MQ2 يرتفع عند تقريب ولّاعة (غاز) — بعد التسخين.
- [ ] HC-SR04 يعطي مسافة صحيحة (قارن بمسطرة) ولا يتأثر كثيراً أثناء البلوتوث.
- [ ] Rain: جاف ≈ 0% ، قطرة ماء ترفع النسبة.
- [ ] كل القيم تظهر في الواجهة مع تاريخ وتحذيرات.
