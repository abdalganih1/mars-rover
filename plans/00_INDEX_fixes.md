## ⚠️ أهم اكتشاف (اقرأه أولاً): تعارض أرجل الشيلد

شيلد المحركات المبني على **شريحتَي L293D** (تصميم Adafruit Motor Shield v1 ونسخه) يستخدم
رقاقة قفل `74HC595` ويحجز هذه الأرجل:

```
محجوز للشيلد: D3, D4, D5, D6, D7, D8, D11, D12   (محركات DC + الـ latch)
سيرفو الشيلد: D9, D10
حرّة فعلياً : D2, D13, A0, A1, A2, A3, A4, A5
محجوز للبرمجة/USB: D0 (RX), D1 (TX)
```

➡️ **طلبك بوضع HC-05 على pins 3 و 4 يتعارض مباشرة مع الشيلد** (D4 = `DIR_CLK`، D3 = PWM للمحرك M2).
لو وصّلت HC-05 عليهم سيتوقف الشيلد عن العمل.

➡️ **الحل المعتمد في هذه الخطط** (يحقق نفس فكرتك: HC-05 على Serial منفصل عبر `SoftwareSerial`،
وإبقاء RX/TX للبرمجة):

```
HC-05  : رجل RX(HC-05)→A4 (عبر Voltage Divider) ، رجل TX(HC-05)→A5 (مباشر)
         بالكود: SoftwareSerial btSerial(A5, A4)  // A5 يستقبل ، A4 يرسل
Rain   : A0   (تناظري — كما طلبت)
MQ2    : A1   (تناظري)
DHT    : D2   (رقمي)
HC-SR04: TRIG=A3 ، ECHO=A2  (تُستخدم كأرجل رقمية)
LED حالة: D13 (الـ LED المدمج)
```

> التفاصيل الكاملة للأسلاك في `03_pinmap_wiring.md`. لو رفضت هذا التوزيع نحتاج
> ترقية إلى **Arduino Mega** الذي يملك أرجلاً كثيرة و4 منافذ Serial عتادية.

## 🤖 سير عمل الوكلاء الفرعيين (Reports Workflow)

كل وكيل فرعي ينفّذ إصلاحاً **يجب** أن:

1. يقرأ الخطة المعنية كاملة + الكود الفعلي قبل التعديل.
2. ينفّذ الإصلاح فعلياً على الملفات.
3. ينشئ ملف تقرير واحد مقابل كل إصلاح داخل مجلد `Reports/`.
4. يسمّي الملف: `Reports/REP_<رقم الخطة>_<معرّف-قصير>.md`
   مثال: `Reports/REP_02_arduino_afmotor.md`
5. يتبع قالب التقرير في `Reports/README.md`.
6. لا يحذف أو يخرّب أي وظيفة شغّالة دون توثيق السبب.

> تفاصيل القالب وقواعد التقارير في `Reports/README.md`.

## 🧩 ملخص الباگات المؤكدة في كود البايثون (مفصّلة في الخطة 05)

1. **`app.py:_emit_sensor_list`** يقرأ `s.min_value` / `s.max_value` وهي غير موجودة
   (الصحيح `min_val` / `max_val`) → استثناء يقتل إرسال قائمة الحساسات.
2. **ربط SocketIO بالحساسات معطّل**: `app.py` يضبط `sensor_manager._socketio` كسمة،
   بينما `sensors.py` يستخدم متغيّر الوحدة العام `_socketio` عبر `init_socketio()`
   الذي لا يُستدعى أبداً → كل أحداث الحساسات تُبتلع بصمت.
3. **بيانات حساسات الأردوينو لا تدخل `SensorManager`**: `bluetooth._data_reader_loop`
   يبثّ القاموس الخام مباشرة كـ `sensor_data` دون استدعاء `sensor_manager.update()`
   → لا تاريخ ولا تحذيرات ولا قصّ مدى. كما يبثّ الـ heartbeat والـ ack كأنها حساسات.
4. **تعارض حالة الأحرف في السيناريوهات**: `scenarios.py` يخزّن `M1/M2/S1/S2` (كبيرة)
   بينما `motors.execute_move` يتوقّع `m1/m2/s1/s2` (صغيرة) أو `direction`
   → خطوات السيناريو **لا تنفّذ أي حركة**.
5. **مسار مطلق ثابت**: `scenarios.SCENARIOS_DIR = "/home/user/program/scenarios"`
   و`config.yaml` فيه مسارات `/home/user/...` → تفشل خارج تلك البيئة.
6. **`motors.py` يدعم محركين فقط** — يحتاج توسعة لـ m3/m4 ولمنطق توجيه 4 عجلات.
