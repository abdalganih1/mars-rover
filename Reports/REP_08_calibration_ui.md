## 1. المشكلة
لم تكن هناك واجهة مستخدم لمعايرة المحركات والسيرفو من الراسبيري. الأردوينو لديه نظام EEPROM
كامل لكنه لا يمكن الوصول إليه بدون تبويبة معايرة في صفحة الإعدادات.

| `templates/settings.html` | تعديل | إضافة تبويبة "🎛️ معايرة الأردوينو" الكاملة (1033 سطر إجمالاً) |

## 3. ما أُضيف

### HTML/CSS (≈230 سطر CSS + HTML)
- تبويبة جديدة `tab-calibration` بين السيناريوهات والعام
- بطاقة "الإعدادات الحالية في EEPROM" — جدول يعرض port_FL/FR/RL/RR وinvert وحدود السيرفو
- **معالج المحركات** بثلاث مراحل (port_id → dir_cal → done) مع:
  - مؤشر خطوات بصري (wstep active/done)
  - شريط تقدم متحرك (0%..100%)
  - مخطط الروبوت التفاعلي (4 عجلات قابلة للنقر)
  - أسئلة ثنائية (نعم/لا) لضبط الاتجاه
- **معالج السيرفو** بأربع مراحل (اختيار → اتجاه → حدود live → مكتمل) مع:
  - منزلق مباشر يحرّك السيرفو حياً عبر `calib_move_servo`
  - أزرار "تعيين من المنزلق" لكل من min/max/center
  - تحقق صحة (min < max، center بين الحدين)
- بطاقة "حفظ في EEPROM" + "إعادة الضبط للمصنع"

### JavaScript (≈220 سطر)
- `mwState`: حالة معالج المحركات (phase, portMap, invertMap, wheelOrder...)
- `swState`: حالة معالج السيرفو
- معالج `socket.on('calib_config')`: يعالج dump/saved/reset_done
- كل أحداث المعايرة مربوطة: `calib_run_port`, `calib_set_map`, `calib_test_dir`, `calib_set_invert`, `calib_move_servo`, `calib_set_servo`, `calib_save`, `calib_get`, `calib_reset`
- تحديث مؤشر التغييرات المعلّقة (`pending-changes`)

## 4. سير الاستخدام

### معايرة المحركات
1. اضغط "🚀 بدء المعايرة"
2. اضغط "▶️ تشغيل المنفذ 1" → اختر العجلة التي تحرّكت من مخطط الروبوت
3. كرّر للمنافذ 2،3،4
4. لكل عجلة: اضغط "اختبار الاتجاه" → أجب "نعم للأمام" أو "لا، اعكسها"
5. اضغط "💾 حفظ في EEPROM"

### معايرة السيرفو
1. اختر S1 أو S2
2. شغّله وأخبر الاتجاه
3. حرّك المنزلق لإيجاد الحدود الميكانيكية → "تعيين من المنزلق"
4. "تأكيد الحدود" → الحفظ

## 5. كيف تم التحقق
- HTML صالح (بنية tabs/phases متسقة)
- كل `socket.emit` يطابق الأحداث الموجودة في `app.py` (F8)
- التحقق من الصحة: min<max وcenter بين الحدين
- لا كسر للتبويبات الأخرى (الكود القائم محفوظ كامل)
